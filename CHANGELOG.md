# Журнал изменений

Сервер MangaFlow (API, источники, синхронизация). У бэкенда нет номеров версий: каждый коммит в `main`
публикует образ `ghcr.io/kotbctakahe/mangaflow-backend:latest`, на сервере он ставится командой `./update.sh`.
Записи сгруппированы по дате обновления. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

Приложение: [mangaflow-app/CHANGELOG.md](https://github.com/KOTBCTAKAHE/mangaflow-app/blob/main/CHANGELOG.md).

## 2026-11-20 — токены сайтов MangaLib (HentaiLib, YaoiLib, MangaLib)

### Исправлено
- Токен из `SOURCE_*_TOKEN` теперь очищается. Можно вставить его как есть: с «Bearer », в кавычках или целиком JSON из Local Storage (`auth`).
- Если сайт отклонил токен (он истёк или выдан другим сайтом сети), в логе `api` появляется предупреждение. Раньше сервер молча работал без токена, и главы 18+ просто не показывались.
- Тайтл без глав кэшируется на 1 минуту вместо 30. После добавления токена главы появляются почти сразу.

### Добавлено
- Команда проверки: `docker compose exec api python -m app.source_check hentailib [slug]`. Она показывает, задан ли токен, принял ли его сайт и чей это аккаунт, сколько глав у тайтла с токеном и без. Заодно команда очищает кэш тайтлов этого источника.

## 2026-11-20 — поиск по сюжету и «Для вас» (для приложения 2.6.0)

### Добавлено
- **Поиск по сюжету**: `GET /search/plot?q=` — описание своими словами → тайтлы с ближайшим сюжетом, сгруппированные по источникам, с фрагментом описания и жанрами. Работает в сервисе `imgindex` рядом с поиском по картинкам.
  - **Гибридный поиск**: смысловые векторы multilingual-e5-base (MIT, ONNX int8, ~280 МБ; usearch f16) плюс BM25 по словам (SQLite FTS5 над основами слов, Snowball для русского и английского). Ранги объединяются методом RRF. Векторы понимают пересказ («гиганты-людоеды» ≈ «титаны»), а слова ловят редкие точные детали («гуль», «причуды», «приют»).
  - **Проверка на 591 описании Shikimori и 34 запросах** («Найди мангу, где…»): нужный тайтл первым — в 65% случаев, в первой тройке — в 82%, в первой десятке — в 94%. Для сравнения: только векторы e5-base — 59 / 68 / 79%, лёгкая e5-small гибридом — 50 / 71 / 97%. Её можно включить через `IMGINDEX_TEXT_MODEL_URL` на слабом сервере.
  - При смене модели векторы пересчитываются сами по сохранённым описаниям.
- **Сбор описаний**: сервис обходит популярное у всех источников без NSFW (до 3000 тайтлов на источник, 30 страниц тайтлов в минуту). Тайтл с одинаковым названием в разных источниках хранится один раз — с самым подробным описанием. Описания из тайтлов, открытых для индексации картинок, тоже идут в дело.
- **Похожие тайтлы**: `GET /manga/{source}/{id}/similar` — соседи по сюжету вперемешку с тем, что читают вместе с этим тайтлом.
- **Лента «Для вас»**: `POST /discover/for-you` (seeds — что нравится, known — вся библиотека, она не предлагается). Разделы: по сюжету (профиль из взвешенных векторов), «Потому что вы читали…», совместное чтение читателей MangaFlow (item-to-item по библиотекам, оценкам и истории за неделю; пара засчитывается, только если за ней хотя бы два читателя, сам спрашивающий не в счёт), оценки друзей ≥ 8, популярное за неделю.
- `tools/plot_eval.py` — проверка качества на описаниях Shikimori.

### Исправлено
- `SHIKIMORI_BASE_URL` по умолчанию — `https://shikimori.io`: shikimori.one с 2026 года отвечает 301, а на переадресации ломается POST при обмене кода OAuth на токен.

## 2026-11-19 — свой поиск по картинкам (для приложения 2.5.0)

### Добавлено
- **Сервис `imgindex`**: свой обратный поиск по картинкам, как SauceNAO, но по страницам наших источников. Модель — SSCD от Meta AI (MIT). Её обучали находить отредактированные копии картинки: с обрезкой, наложенным текстом, другим масштабом или скриншотом экрана. Работает на CPU через onnxruntime, около 0,1 с на фрагмент. Векторы лежат в usearch (HNSW, int8), данные о страницах — в SQLite, всё в томе `imgindex-data`.
- **Что индексируется.** Каждая страница сохраняется целиком плюс три горизонтальные полосы (ряды кадров). Развороты делятся пополам, ленты вебтунов режутся на перекрывающиеся окна.
- **Очередь.** Сначала индексируются главы, которые читают: `PUT /progress` и `POST /progress/batch` ставят их в очередь. Затем в фоне идёт обход популярного у всех источников без NSFW: до 300 тайтлов на источник, 30 глав на тайтл вразброс. Тайтл, уже взятый из другого источника, повторно не индексируется. Скорость — 40 страниц в минуту; страницы из кэша прокси не скачиваются заново. Если источник недоступен, повторная попытка — через час.
- **Ответ поиска.** Если найдено, `POST /lookup/image` получает движок **MangaFlow**: точный источник, тайтл, главу и страницу (`source_id`, `manga_id`, `chapter_id`, `page_index`). Карточка этого тайтла идёт первой в результатах.
- **Калибровка** на 243 страницах MangaDex с шестью видами правок: при 60% и выше другой тайтл не нашёлся ни разу; скриншот телефона, кадр ТикТока и подписи поверх находятся в 98–100% случаев, вырезанный кадр — в 88%. Уверенность: ≥ 70% — «точно», ≥ 60% — «похоже», порог показа — 52%. Скрипт оценки — `tools/imgindex_eval.py`.
- Модель экспортируется воркфлоу `model.yml` в релиз `model-sscd-v1` и скачивается сервисом при первом запуске (98 МБ, сверяется по sha256).

### Сервер
- `./update.sh` сам добавит сервис `imgindex` в compose. Нагрузка: ~400 МБ RAM плюс ~0,7 ГБ на миллион фрагментов (по умолчанию максимум 1,5 млн, `IMGINDEX_MAX_VECTORS`), 2 ядра CPU (`IMGINDEX_THREADS`). Остальные настройки описаны в `.env.example`.

## 2026-11-19 — поиск по скриншоту точнее (для приложения 2.4.2)

### Улучшено
- SauceNAO опрашивается только по базам манги (Madokami, MangaDex) и аниме (`dbmask`), с `hide=2`. Арт-борды и H-базы больше не дают ложных названий.
- Пороги совпадения: trace.moe — 90%, манга — 50%, аниме в SauceNAO — 70%. Добавлена уверенность `confidence` (`high` / `medium` / `low`). Совпадение двух движков по одному тайтлу повышает уверенность, и они сливаются в один вариант.
- Новое поле `candidates`: до трёх вариантов, у каждого свои `results`. В них только тайтлы, чьё название совпадает с одним из названий варианта (`title_matches`), а не все результаты текстового поиска.
- Русские названия ищутся на MangaDex и по названию, если у совпадения нет `md_id`. Взрослые аниме из trace.moe отсекаются.

## 2026-11-19 — поиск по скриншоту, второй заход (для приложения 2.4.1)

### Улучшено
- `POST /lookup/image` опрашивает несколько движков параллельно: **SauceNAO** (если задан ключ) и **trace.moe** (без ключа, кадры аниме → манга-первоисточник через связи AniList).
- Для совпадений с MangaDex подтягиваются русские альтернативные названия; поиск по источникам идёт по нескольким названиям сразу (русское первым), плюс прямые карточки MangaDex.
- Порог SauceNAO для манга-индексов снижен до 42% (переведённые сканы), для остальных — 60%; запрашивается 16 результатов.
- В ответе новое поле `engines` — статус каждого движка (`ok`, `nothing`, `no_key`, `error`). Без ключа SauceNAO эндпоинт больше не отвечает 503, а работает через trace.moe.

## 2026-11-19 — соцфункции и трекеры (для приложения 2.4)

### Добавлено
- **Друзья:** заявки по нику, список с тем, что друг читает сейчас, профиль друга, лента активности за 30 дней.
- **Оценки** 1–10 с отзывом, оценки друзей и средняя оценка тайтла.
- **Советы тайтлов** друзьям.
- **Комментарии к главам** с лайками и привязкой к странице.
- **Трекеры Shikimori, MyAnimeList, AniList:** вход через OAuth на сервере (приложение не видит токены), автоматическая отправка прочитанных глав и оценок, поиск тайтла по названию и альтернативным названиям, ручная привязка, «отправить прогресс всей библиотеки».
- **Комнаты «Читать вместе»** на WebSocket: синхронные страницы, реакции, сообщения; несколько воркеров связаны через Redis pub/sub.
- **Поиск по скриншоту** через SauceNAO с поиском найденного тайтла в источниках.
- Миграция БД `0002` (применяется сама при старте).

### Настройка
- Новые переменные `.env`: `SAUCENAO_API_KEY`, `SHIKIMORI_CLIENT_ID/SECRET`, `MAL_CLIENT_ID/SECRET`, `ANILIST_CLIENT_ID/SECRET`, рекомендуется `PUBLIC_BASE_URL`. Примеры — в `infrastructure/.env.example`.
- nginx: проксирование WebSocket для `/api/v1/rooms/`.

## 2026-11-19 — обложки, nginx, новые источники

### Исправлено
- Картинки продолжают работать, если том кэша недоступен для записи (запасная папка, ответ из памяти).
- nginx сохраняет `X-Forwarded-Proto` от HTTPS-прокси перед ним — ссылки на картинки больше не становятся `http://`.
- Desu: переход на новый API `/api/manga` (старый отвечал 410). Acomics: страницы 18+ за проверкой возраста.
- AllHentai и HentaiLib сообщают «нужен аккаунт» вместо ошибки 404.
- Авторизация: повторное использование только что обновлённого refresh-токена в течение 120 с считается гонкой, а не кражей — вместо выхода выдаётся новая пара.

- Диагностика на сервере: `tools/live_check.py` (проверка источников) и `tools/image_check.py` (путь картинок).
